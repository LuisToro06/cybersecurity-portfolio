# Security Incident Reporting

## Objective

Teach users how to recognize suspicious activity and report it through an appropriate security process.

## Recommended Process

1. Stop interacting with suspicious content.
2. Preserve relevant evidence.
3. Record what was observed.
4. Report the event using the organization's designated channel.
5. Follow instructions from the security or incident response team.
6. Do not independently delete or modify evidence unless instructed.

## Examples of Reportable Events

- Suspected phishing
- Unexpected authentication requests
- Suspected credential compromise
- Suspicious downloads
- Loss of a device containing sensitive information
- Unauthorized disclosure of information
- Other suspicious cybersecurity events

## Key Learning Point

Early and appropriate reporting can support timely detection, analysis, response, and recovery.
